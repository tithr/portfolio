por quê

o primeiro commit trava mais gente do que o código.

todo tutorial de git começa supondo que você já sabe o que é um repositório, um remote e uma branch. quem está começando não trava na lógica: trava no medo de fazer errado em um lugar público. eu fiz esse guia partindo do zero. no final você tem um link funcionando.

o guia

cinco passos.

0 de 5 concluídos

  1. crie uma conta em github.com. Depois instale o git no seu computador: no macOS, basta abrir o Terminal e digitar git --version, que o sistema oferece a instalação. No Windows, baixe em git-scm.com.

    para conferir se deu certo, o comando abaixo precisa responder com um número de versão.

    git --version

  2. o git assina cada mudança com um nome e um e-mail. você faz isso uma vez só. use o mesmo e-mail da conta do GitHub para que os commits apareçam no seu perfil.

    git config --global user.name "seu nome" git config --global user.email "seu@email.com"

  3. abra o terminal dentro da pasta do seu projeto. O primeiro comando cria o repositório, o segundo marca todos os arquivos e o terceiro salva esse estado com uma mensagem. Commit é só isso: uma foto do projeto com um bilhete explicando.

    git init git add . git commit -m "primeiro commit"

    nada disso vai para a internet ainda. Até aqui tudo acontece só no seu computador, e é por isso que não há como estragar nada.

  4. no GitHub, clique em New repository, dê um nome e crie sem marcar nenhuma opção extra. A tela seguinte mostra um endereço terminado em .git. Troque os dois campos abaixo pelos seus e copie os comandos prontos.

    git remote add origin https://github.com/tithr/meu-projeto.git git branch -M main git push -u origin main

    na primeira vez o git vai pedir login. Use a janela do navegador que abre, ou um token em vez da senha: o GitHub não aceita mais a senha da conta no terminal.

  5. se o seu projeto tem um index.html, ele pode virar um site em um minuto. No repositório, vá em Settings, depois Pages, e em Branch escolha main e a pasta raiz. Salve e espere um pouco.

    o endereço do seu site fica assim:

    https://tithr.github.io/meu-projeto/

    a partir daqui o ciclo é sempre o mesmo: mudar um arquivo, git add ., git commit -m "o que mudou" e git push. É o mesmo comando que publicou este guia.

pronto. Sua primeira ideia está pública, com endereço e tudo.

comecei escrevendo tudo corrido e não funcionava. quem está começando se perde no meio de um parágrafo longo. quebrar em passos que abrem um por vez, com uma caixa para marcar, mudou tudo. na próxima versão quero repensar o passo 4 — ele depende de uma tela do GitHub que muda de tempos em tempos.
